# Initial Data Dictionary

**Status:** Implemented as the provisional local synthetic slice; review required before real data
**Date:** 2026-09-25

Every node written by the package is keyed and queried by `workspace_id`. The first deployment is single-user and local. `workspace_id` is therefore a data partition and not a substitute for multi-user authorization.

| Label | Required properties | Optional properties in current implementation | Identity |
|---|---|---|---|
| `Workspace` | `id`, `created_at` | `name` | `id` unique |
| `Project` | `workspace_id`, `id`, `name`, `source_system`, `source_id`, `created_at`, `updated_at` | `status`, `summary`, `start_at`, `due_at` | `(workspace_id, id)` unique |
| `Task` | `workspace_id`, `id`, `name`, `source_system`, `source_id`, `created_at`, `updated_at` | `status`, `priority`, `description`, `due_at`, `completed_at` | `(workspace_id, id)` unique |
| `Client` | `workspace_id`, `id`, `name`, `source_system`, `source_id`, `created_at`, `updated_at` | `external_ref`, `website` | `(workspace_id, id)` unique |
| `Partner` | `workspace_id`, `id`, `name`, `source_system`, `source_id`, `created_at`, `updated_at` | `external_ref`, `website` | `(workspace_id, id)` unique |
| `Person` | `workspace_id`, `id`, `name`, `source_system`, `source_id`, `created_at`, `updated_at` | `external_ref`, `email` | `(workspace_id, id)` unique |
| `Document` | `workspace_id`, `id`, `title`, `mime_type`, `source_system`, `source_id`, `checksum`, `updated_at` | `source_uri` | `(workspace_id, id)` unique; source tuple identifies repeat ingestion |
| `DocumentChunk` | `workspace_id`, `id`, `ordinal`, `text`, `locator`, `embedding`, `embedding_model`, `embedding_dimensions`, `updated_at` | — | `(workspace_id, id)` unique |

## Relationships

| Relationship | Direction | Intended use and metadata |
|---|---|---|
| `CONTAINS` | Workspace → project/entity/document | Workspace ownership/grouping; generated by upsert/ingestion |
| `HAS_TASK` | Project → Task | Project task membership; `provenance`, `review_state`, `updated_at` |
| `FOR_CLIENT` | Project → Client | Project client association; same link metadata |
| `WITH_PARTNER` | Project → Partner | Project partner association; same link metadata |
| `ASSIGNED_TO` | Person → Task | Task assignment; same link metadata |
| `PARTICIPATES_IN` | Person → Project | Project participation; same link metadata |
| `RELATES_TO` | Document → Project/Task/Client/Partner/Person | Explicit document association; provenance and review state are recorded |
| `HAS_CHUNK` | Document → DocumentChunk | Document text split into cited chunks |

Allowed link provenance values are `USER_LINKED`, `IMPORTED`, and `EXTRACTED`. Review state values are `USER_LINKED`, `IMPORTED`, `PROPOSED`, and `REVIEWED`. Extracted links should normally start as `PROPOSED`; current tools do not run automatic entity extraction.

## Identity, history, and limitations

- Project/entity IDs are supplied by the caller and must be stable within a workspace. Source system and source ID are stored separately for lineage.
- Document IDs are deterministic UUIDv5 values from workspace, source system, and source ID. Chunk IDs also include ordinal and chunk text digest.
- Re-ingestion with identical document source/content keeps stable identities. Changed content replaces chunks for that document. The current implementation does not preserve old document versions.
- Current upserts replace the supported entity properties. The current slice has no `Claim` node, general event log, alias-resolution/merge model, `valid_from`/`valid_to` history, retention job, or multi-user permission model.
- Task state is stored as a property and returned by a structured Cypher query. Historical state is not retained in this first slice.
- Text locators use 1-based source line ranges. PDF page, Word section, image, table, and audio locators are outside the initial scope.
- The schema and indexes are initial implementation decisions for a local synthetic demonstration. They are not a production migration contract.
